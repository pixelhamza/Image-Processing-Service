# Image Processing Service

A backend service for secure image upload, transformation, and retrieval using AWS S3, presigned URLs, and a scalable architecture designed for future growth.

---

### System Design
![image_alt](https://github.com/pixelhamza/Image-Processing-Service/blob/main/architecture.png)
## Description

This service allows authenticated users to upload images, apply transformations, and retrieve images securely. Images are stored privately in AWS S3 and are never exposed directly. Access to images is controlled through short-lived presigned URLs generated by the backend.

The system is designed with scalability in mind, supporting Redis-based caching, rate limiting, and an asynchronous processing model for future enhancements.
## Core Functionality

### Cloud Storage (AWS S3)
- Images are stored in a private S3 bucket
- No public access to stored images

### Presigned URLs
- Images are accessed using time-limited presigned URLs
- Clients download images directly from S3
- Backend fully controls access and expiration

### Image Transformations
- Supports resize, crop, rotate, and filter operations
- Transformations generate new immutable images
- Original images are never modified
- Image processing is handled using Sharp

### Redis Caching
-caches the recently transformed images to avoid databse lookup

### Rate Limiting
- Per-user rate limiting on transformation endpoints
- Implemented using Redis
## Future Improvement
### Message Queue 
- Architecture supports asynchronous image transformations
- Transform requests can be processed in background workers
- Designed to return job-based responses (`202 Accepted`)
- Improves scalability and request latency

- Task given by https://roadmap.sh/projects/image-processing-service
